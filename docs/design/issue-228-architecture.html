Orchestrate: no finish gate demands a worker the quota refuses

Session 227f7f480afa ran 3h27m, failed, and claimed a green suite with 4 failing tests. The five fixes in issue 228 touch four modules (Orchestrate, Provenance, SpawnAgent, Agents.Quota), so this page is the architecture gate. Approving it settles the five changes and the two open choices in section 2.

In plain words

The coordinator can hire a fixed number of helpers per run. Today it cannot see how many it has left, it is punished when the last one is refused, and the final checks still order it to hire more. Trimmed test output hides failures, so failing tests read as passing. We show the count, stop demanding helpers once none are left, list what went unchecked, and read test output for failures.

1. What breaks, and the change

DefectTodayChange
1 ask_user auto-delegates the step the user is answering A successful ask_user resets turns_without_spawn to 0 in watchdog/2
2 piped tests green on mix test x | tail -60 with 4 failures Provenance records {:failed_command, _} when a test command's output shows a failure summary (ExUnit, pytest, jest/vitest, go, cargo, rspec, phpunit, dotnet, gradle/mvn, compile error). coverage_note/1 names the command it saw instead of asserting “the suite is green”
3 gates demand a spawn the quota refuses With spawned >= limit, gates 1–4 let finish through and append an “Unverified” list to the deliverable
4 refusal counted, says “do the work yourself” {:error, :uncounted, text}. A delegate-only caller reads “finish now and name what is unverified”. Same wording in auto_delegate/2
5 allowance invisible until refused Every spawn result and refusal ends [runtime] worker 9 of 10 this run; 1 left.

How SpawnAgent knows the caller holds no tools. Orchestrate.init/1 sets assigns[:delegate_only]; SpawnAgent clears it on every child. :strict_spawn cannot serve: workers inherit it.




2. Open choices





A. Repeat refusals. ExAthena.Tool documents the
counted refusal as the bound on a crash loop. The orchestrator runs with
max_iterations: :infinity. If every refusal is uncounted, a model
that varies its brief each time is bounded only by the no-progress guard.
Proposed: the first refusal is uncounted, later ones are counted.







B. Summary cut off. mix test | head -80 can drop
the summary line. Proposed: a piped test command whose output shows no summary
line at all is not a passing run for tested?.
