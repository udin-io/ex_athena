A worker’s report is its last message

Worker subagent_fqB0WqCf ran 794,377 input tokens and 17 minutes, wrote its codebase map, then ended with 545 characters saying the map was “delivered in the previous turn”. That is all the parent got, all read_worker_report had, and the parent re-spawned: another 838,180 tokens. This page is the architecture gate for issue 251. Approving it settles what goes on disk, where the recovery happens, and two tuning knobs.

In plain words

A helper works for an hour, writes up what it found, then signs off with “see my write-up above” — and only that sign-off is passed on. Nobody kept a copy, so the hour is repeated. We start keeping the helper’s own prose, and when its last words point at something longer, we pass the longer thing too.

1. What breaks

The orchestrator did everything right. It noticed and called read_worker_report with the correct id. The tool answered with the same boilerplate: the report existed in exactly one place, Result.messages, which nothing reads and nothing writes down.

2. What this ticket does

Both directions the ticket offers, sharing one detector.

  • New ExAthena.Agents.Report: assistant_texts/1 pulls a Result’s assistant prose; recover/2 appends the longest earlier message, labelled, when the final one is far shorter.
  • Sidechain persists that prose beside text — assistant text only, never tool results.
  • SpawnAgent recovers in band, before truncate_result/3, so result_chars bounds it and the existing notice addresses the rest.
  • ReadWorkerReport composes the same string, so from: means the same on both paths.
  • Two knobs via Tuning and Settings.schema/0; one line added to the worker suffix.

Disk. One capped copy of a worker’s prose in the jsonl the run already writes. Tool results are the bulk of a transcript; none are stored.

3. Not in scope

  • Making models behave.
  • Streaming prose to disk as it is produced. This reads Result.messages at hand-back, so a report that context compaction dropped mid-run stays unrecoverable.
  • A third source: value on read_worker_report.

4. Definitions

TermHere it means
self-summaryA final message far shorter than an earlier one, pointing at it instead of repeating it.
summary_recovery_ratioTimes longer the earlier message must be before it is handed back. Default 4; 0 disables.
report_transcript_charsAssistant prose kept per worker on disk. Default 100,000; 0 disables.
in bandAppended to the spawn result, no extra tool call.
